# ADR 0002: Operation commit signing — SSH and PGP signature formats

## Status
Accepted

## Context

git-bug stores bug and identity operations as git commits under `refs/bugs/` and `refs/identities/`. These commits can be signed to prove they were authored by the claimed Identity. The current implementation uses OpenPGP armored detached signatures stored in the git commit's `gpgsig` header (`commit.PGPSignature` in go-git). This is tightly coupled to the OpenPGP key format being abandoned in ADR-0001.

Two goals drive the signing format decision:

1. **`git verify-commit` interoperability.** Users who already sign their git commits should be able to use the same key and tooling for git-bug operation commits. `git verify-commit` should work without extra configuration.

2. **Algorithm-agnostic keys.** With Ed25519 and other modern algorithms supported via ADR-0001, the signing format must accommodate multiple algorithms — not just RSA via OpenPGP.

Git supports two signing formats in the `gpgsig` commit header:
- **PGP format** (`-----BEGIN PGP SIGNATURE-----`): verified with `gpg`, `git verify-commit` using `gpg.format = openpgp` (the default)
- **SSH format** (`-----BEGIN SSH SIGNATURE-----`, `PROTOCOL.sshsig`): verified with `ssh-keygen -Y verify`, `git verify-commit` using `gpg.format = ssh` (supported since git 2.34, released November 2021)

Both formats are stored in the same `gpgsig` commit field. git-bug performs its own verification (via go-git + crypto libraries) rather than shelling out to gpg or ssh-keygen, so git-bug can use either format regardless of the user's local git config.

The alternative of picking one format for all keys was rejected because it would force GPG users to reconfigure their tools and SSH users to install GPG.

## Decision

The signature format used for an operation commit follows the origin of the signing key:

- **SSH-origin keys** (from `user.signingkey` with `gpg.format = ssh`, or Ed25519 keys generated by `git bug user key generate`): sign using SSH signature format (`PROTOCOL.sshsig`) via `golang.org/x/crypto/ssh`. This is already a transitive dependency.
- **GPG-origin keys** (from `user.signingkey` with `gpg.format = openpgp`, or imported from a provider's GPG keys API): sign using PGP armored detached signature format via `github.com/ProtonMail/go-crypto/openpgp`.

The key's origin is recorded alongside the key at import time, so the signing path does not need to inspect the key bytes to determine the format.

Verification mirrors signing: if the commit carries an SSH-format signature, verify using `golang.org/x/crypto/ssh`; if PGP-format, verify using OpenPGP. The `deArmorSignature` function in `repository/common.go` is replaced by a format-detecting dispatcher.

`StoreSignedCommit` in `repository/gogit.go` is updated to accept a signer interface rather than `*openpgp.Entity`, and the `RepoData.StoreSignedCommit` signature changes accordingly.

For users who already sign commits, `git bug user new` and `git bug user adopt` read `gpg.format` and `user.signingkey` from git config and import the key. This means `git verify-commit` on git-bug operation commits works with the user's existing tooling and zero additional configuration.

## Consequences

- `git verify-commit` works on git-bug operation commits for both SSH and GPG users without reconfiguration.
- The same Ed25519 key can be used for both git-bug operations and regular git commits (configured via `gpg.format = ssh` + `user.signingkey`).
- git-bug Identities become a distributed public key infrastructure: collaborators who pull the repo can verify signed commits from any Identity they have.
- The `PGPEntity()` method on `Key` is removed. The OpenPGP dependency is retained for GPG-origin key signing and for parsing `pgpEntity` blobs at import time, but is no longer the sole signing path.
- Users who have neither a GPG key nor an SSH key configured get unsigned operation commits. This is acceptable — unsigned commits are valid; signing is an optional integrity guarantee, not a gate. See also ADR-0003 for how the server signs on behalf of web users.
